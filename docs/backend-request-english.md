# 영어 UI 지원을 위한 백엔드 요청

작성일: 2026-11-18
상태: 요청. 프런트 구현은 끝났습니다(2026-11-20). 서버가 아래 필드를 내려주기 시작하면 추가 배포 없이 영어 표시와 관리자 영어 입력칸이 켜집니다.
관련 문서: [english-ui-spec.md](./english-ui-spec.md)

## 1. 요약

방문자 화면에 영어를 지원합니다. 버튼·메뉴 같은 화면 틀은 프런트가 처리하고, 서버에는 네 가지가 필요합니다.

1. 운영진이 입력하는 내용에 **영어 저장 칸** 추가
2. 관리자 화면에서 쓸 **번역 API** (DeepL 호출을 서버가 대신)
3. 이미 등록된 내용의 **일괄 번역**
4. 지도 도면의 **영어 이미지 주소**

하지 않아도 되는 것: 오류 문구의 영어화(프런트가 `error.code`로 영어 문구를 고릅니다), 문자·알림 문구의 영어화(한국어 유지), `Accept-Language` 처리.

## 2. 영어 저장 칸

모두 NULL 허용입니다. 영어가 비어 있으면 프런트가 한국어 값을 대신 보여주므로 서버에서 대체할 필요는 없습니다.

영어는 한국어보다 글자 수가 많아 길이 제한을 따로 둡니다. 프런트 입력칸이 아래 길이로 막고 있으니 서버도 같은 값으로 맞춰 주세요.

| 필드 | 최대 길이 |
| --- | --- |
| 부스·시설 `nameEn`, 공연 `titleEn`, 무대·축제 `nameEn` | 40 |
| 부스·시설 `placeEn`, 공지 `titleEn` | 60 |
| 부스·공연 `descriptionEn` | 1000 |
| 공지 `contentEn` | 2000 |

**켜지는 조건**: 프런트는 `GET /festival` 응답에 `nameEn` 키가 있는지로 서버의 영어 지원 여부를 판단합니다. 값이 없어도 `"nameEn": null`로 키는 반드시 내려주세요. 이 키가 없으면 관리자 화면에 영어 입력칸이 나오지 않고, 저장 요청에도 `…En` 필드를 싣지 않습니다. 그래서 2장 전체(조회 응답과 등록·수정 요청)가 준비된 뒤에 이 키를 내려주셔야 합니다.

| 테이블 | 추가 컬럼 | 응답·요청 필드 |
| --- | --- | --- |
| `booth` | `name_en`, `description_en`, `place_en` | `nameEn`, `descriptionEn`, `placeEn` |
| `notice` | `title_en`, `content_en` | `titleEn`, `contentEn` |
| `performance` | `title_en`, `description_en` | `titleEn`, `descriptionEn` |
| `facility` | `name_en`, `place_en` | `nameEn`, `placeEn` |
| `stage` | `name_en` | `nameEn` |
| `festival` | `name_en` | `nameEn` |

- **조회 응답**: 방문자·관리자 API 모두 기존 필드 옆에 `…En` 필드를 추가해 주세요(없으면 `null`). 공연 응답의 `stageName` 옆에도 `stageNameEn`이 필요합니다.
- **등록·수정 요청**: 관리자 API가 `…En` 필드를 선택 값으로 받습니다. 빈 문자열은 `null`로 저장해 주세요.
- 번역 결과가 길이 제한을 넘으면 프런트가 저장을 막고 줄이도록 안내합니다. 서버는 넘는 값을 `400 C001`로 거절하면 됩니다.
- 테이블·컬럼 이름은 현재 스키마에 맞게 조정하셔도 됩니다. 프런트는 응답 필드 이름만 봅니다.

## 3. 번역 API

번역 서비스의 키를 프런트에 둘 수 없어 서버가 대신 호출합니다.

### `POST /admin/translate`

관리자 세션 + CSRF 필요. 부스 관리자도 자기 부스를 수정하므로 `SUPER_ADMIN`과 `BOOTH_ADMIN` 모두 허용.

요청:

```json
{ "texts": ["총학생회 주점", "닭꼬치와 맥주를 판매합니다."], "target": "EN" }
```

응답 `data`:

```json
{ "translations": ["Student Council Pub", "We sell chicken skewers and beer."] }
```

| 항목 | 규칙 |
| --- | --- |
| `texts` | 1~10개, 각 1~1000자. 순서를 유지해 같은 개수로 돌려줌 |
| `target` | 지금은 `EN`만. 다른 값은 `400 C001` |
| 원문 언어 | 한국어 고정(`source_lang=KO`) |
| 번역 서비스 실패·한도 초과 | `503`과 코드 `T001`, 메시지 "자동 번역을 사용할 수 없습니다. 영어를 직접 입력해 주세요." 프런트는 이 문구를 영어 칸 아래에 보여주고 등록은 계속 진행할 수 있게 합니다 |
| 요청 제한 | 계정당 분당 30건 정도 |
| 키 | 환경 변수(`DEEPL_API_KEY`). 비어 있으면 항상 `503 T001` |

번역 서비스는 DeepL 무료 플랜으로 시작하는 것으로 정했습니다. 번역량은 부스·공지 수십 건 수준으로 예상하지만, 무료 한도와 약관은 가입 시점에 직접 확인해 주세요(프런트 쪽에서 확인하지 못했습니다). 고유 명칭(청심대, 노천극장 등)은 DeepL 용어집으로 고정할 수 있으면 좋습니다.

## 4. 기존 데이터 일괄 번역

이미 등록된 부스·공지·공연·시설·무대·축제의 영어 칸이 비어 있습니다. 한 번 실행하는 스크립트나 관리자 전용 API로 채워 주세요.

- 영어 칸이 `NULL`인 행만 번역(운영진이 고친 값은 건드리지 않음).
- 실패한 행은 건너뛰고 건수만 기록.

## 5. 지도 도면의 영어 이미지

`MapFloorplan` 응답에 `imageUrlEn`(없으면 `null`)을 추가해 주세요. 영어 지도는 한국어 지도와 같은 크기·같은 배치로 제작하므로 핀 좌표는 그대로 씁니다. 관리자가 도면을 등록·수정하는 API가 있다면 같은 필드를 받도록 해 주세요.

## 6. 프런트 동작 (참고)

- 영어 화면에서 `nameEn || name`처럼 영어 값이 있으면 영어, 없으면 한국어를 씁니다.
- 관리자 등록 화면에서 한국어 입력칸을 벗어날 때 영어 칸이 비어 있으면 `POST /admin/translate`를 호출해 채웁니다(칸 하나당 `texts` 1개). 운영진이 영어 칸을 직접 고친 뒤에는 자동으로 덮어쓰지 않고, "다시 번역" 버튼을 눌렀을 때만 다시 호출합니다.
- 저장을 누른 시점에 한국어는 있는데 영어가 비어 있는 칸이 남아 있으면, 그 칸들을 한 번의 요청(`texts` 여러 개)으로 번역한 뒤 저장합니다. 번역이 실패하면 영어 없이(`null`) 저장합니다.
- 영어 화면에서 언어를 바꾸면 축제·부스·공지 목록을 다시 조회합니다.
- 검색(부스 이름 등)은 프런트에서 한국어·영어 이름을 모두 대상으로 합니다. 서버 검색 API는 바꾸지 않아도 됩니다.
