# 영어 UI 지원 명세

작성일: 2026-11-18
상태: 1~3차 구현 완료(2026-11-18). 4차(운영진 입력 내용의 영어화)는 서버 작업 대기
관련 문서: [backend-request-english.md](./backend-request-english.md) (서버 요청)

## 1. 방향

외국인 방문자가 축제 앱을 영어로 쓸 수 있게 한다. 화면 틀(버튼·메뉴·안내 문구)은 프런트가 번역 파일로 바꾸고, 운영진이 입력하는 내용(부스·공지·공연 등)은 관리자 화면에서 자동 번역을 추천받아 영어를 함께 저장한다.

## 2. 결정 사항

| # | 항목 | 결정 |
| --- | --- | --- |
| 1 | 대상 범위 | 방문자 화면만 영어 지원. 관리자 화면(`/admin/*`)은 항상 한국어 |
| 2 | 운영진 입력 내용 | 관리자 등록 화면에 영어 입력칸을 두고, 자동 번역 결과를 미리 채운 뒤 운영진이 고쳐서 저장 |
| 3 | 언어 결정 | 기기 언어가 한국어면 한국어, 아니면 영어. 사용자가 직접 바꾸면 기기에 저장(`localStorage`의 `kufim.lang`). 주소는 바꾸지 않음(`/en/...` 없음) |
| 4 | 전환 버튼 | 홈 상단(알림 종 옆)과 전체 메뉴에 `KO / EN` |
| 5 | 영어 문구 | Claude가 초안 작성, 고유 명칭(청심대, 노천극장, 상황실 등) 표기만 사람이 검수 |
| 6 | 언어 수 | 영어만. 언어 파일을 추가하면 세 번째 언어가 붙는 구조 |
| 7 | 문자·알림 | 서버가 보내는 문자와 알림 문구는 한국어 유지. 알림함 화면의 틀만 영어 |
| 8 | 서버 오류 문구 | 프런트가 오류 코드(`A003`, `L001` 등)를 보고 영어 문구로 바꿈. 모르는 코드는 일반 영어 문구 |
| 9 | 지도 | 영어 지도 이미지를 따로 제작(디자인 담당). 언어에 따라 다른 이미지를 표시 |
| 10 | 구현 도구 | `react-i18next`. 문구는 `src/i18n/ko.ts`, `src/i18n/en.ts`(영어 파일에 빠진 문구가 있으면 타입 검사에서 걸림) |
| 11 | 테스트 | 기존 테스트는 한국어로 고정(Playwright `locale: 'ko-KR'`). 영어는 전환과 주요 화면만 새 테스트 |
| 12 | 진행 | PR 3번 + 서버 준비 후 1번(4장) |
| 13 | 영어 칸을 둘 항목 | 부스(이름·소개·위치), 공지(제목·본문), 공연(제목·소개), 시설(이름·위치), 무대 이름, 축제 이름. 출연진·셋리스트·운영 시간·습득물·신고 내용은 한국어 그대로 |
| 14 | 번역 시점 | 한국어 입력칸에서 벗어났을 때 영어 칸이 비어 있으면 자동으로 채움. "다시 번역" 버튼 제공. 운영진이 손으로 고친 영어는 덮어쓰지 않음 |
| 15 | 번역 서비스 | DeepL(무료 한도로 시작). 정확한 한도·가격은 서버 담당자가 가입 시 확인 |
| 16 | 영어가 비어 있을 때 | 한국어 원문을 그대로 표시 |
| 17 | 기존 데이터 | 서버에서 한 번 일괄 자동 번역, 운영진이 필요한 것만 수정 |
| 18 | 서버 준비 전 | 화면 틀 영어화를 먼저 배포. 운영진 입력 내용의 영어화는 서버 준비 후 |
| 19 | 영어 지도 위치 | 서버 도면에 영어 이미지 주소 칸 추가. 프런트에 들어 있는 고정 이미지는 프런트에서 교체. 영어 이미지가 없으면 한국어 지도 표시 |
| 20 | 영어 지도 규격 | 한국어 지도와 같은 크기·같은 배치, 글자만 영어(핀 위치가 퍼센트 좌표라 어긋나면 안 됨) |

## 3. 프런트 구조

- `src/i18n/index.ts`: 초기화, 언어 감지·저장, `setLanguage()`.
- `src/i18n/ko.ts`, `en.ts`: 화면별로 묶은 문구.
- `/admin/*` 경로에서는 저장된 선택과 무관하게 한국어로 표시한다. 방문자 화면으로 나오면 원래 선택으로 돌아간다.
- `<html lang>`을 현재 언어에 맞춘다.
- 서버 코드값(공지 분류, 부스 주최, 시설 유형, 신고 상태 등)의 표시 이름은 번역 파일에서 가져온다. 기존 코드는 한국어 표시 이름을 내부 키로도 쓰므로(`codeFor`, `notices.find(n => n.category === '긴급')`), 내부 키는 그대로 두고 화면에 그릴 때만 번역한다.
- 날짜·경과 시간("3분 전", "11월 11일")은 언어별 형식 함수로 바꾼다.
- 운영진 입력 내용은 서버가 영어 값을 내려주면 영어 화면에서 그 값을 쓰고, 없으면 한국어 값을 쓴다.

## 4. 진행 단계

| 단계 | 내용 | 서버 필요 |
| --- | --- | --- |
| 1차 PR | 도구 설치, 언어 감지·전환 버튼, 홈·전체 메뉴·하단 메뉴 | 아니오 |
| 2차 PR | 부스, 공연, 공지·알림함, 지도, 웨이팅 | 아니오 |
| 3차 PR | 신고, 분실물센터, 이용 안내, 오류 문구(코드 → 영어) | 아니오 |
| 4차 | 운영진 입력 내용의 영어 표시, 관리자 등록 화면의 영어 칸·자동 번역, 영어 도면 | 예 |

## 5. 검증 체크리스트

- [ ] 기기 언어가 영어인 브라우저로 처음 들어오면 영어로 보인다
- [ ] `KO / EN`으로 바꾼 선택이 새로고침·재방문 후에도 유지된다
- [ ] 관리자 화면은 영어를 선택한 상태에서도 한국어다
- [ ] 영어 화면에서 가로 넘침·잘림이 없다(영어가 한국어보다 길다)
- [ ] 영어가 없는 운영진 입력 내용은 한국어로 보인다
- [ ] 기존 한국어 테스트가 모두 통과한다
