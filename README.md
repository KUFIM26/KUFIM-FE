# KUFIM (Konkuk University Festival Information Map)

대학 축제 방문객에게 행사 정보·지도·QR 웨이팅을 제공하고, 운영진이 콘텐츠와 부스 대기 현황을 관리할 수 있도록 개발한 모바일 웹 서비스입니다.

- **개발 기간**: 2026.08. ~ 진행 중
- **개발 인원**: 2명 — 김도현: PM·프론트엔드 / 정근녕: 백엔드
- **담당 역할**: PM, 서비스 기획, UI 설계 및 프론트엔드 구현
- **프로젝트 상태**: 시연용 개발 완료. 2026년 10월 28일 축제에서 실제 도입 및 필드테스트 예정
- **배포 링크** : https://kufim-fe.vercel.app

## 1. 프로젝트 소개

지난 2년간 대학 축제를 직접 기획·운영하며 겪은 불편과 어려움을 바탕으로 프로젝트를 시작했습니다.
방문객이 행사 정보와 부스 위치, 자신의 대기 상태를 확인하고, 운영진이 현장 콘텐츠와 웨이팅을 관리하는 흐름을 하나의 서비스에 담았습니다.

- **방문객**: 공연·부스·시설·공지 조회, 지도 탐색, QR 웨이팅 접수와 확인
- **운영진**: 콘텐츠 등록·수정, 부스별 호출·입장 처리, 무대 구역 혼잡도 입력

현재는 시연용 구현을 마쳤으며, 실제 현장에서의 사용성과 트래픽 대응 수준은 예정된 필드테스트를 통해 확인할 계획입니다.

## 2. 주요 화면 및 기능

| 기능 | 주요 동작 |
| --- | --- |
| 축제 정보 탐색 | 공연 일정과 부스·시설·공지 조회 |
| 행사장 지도 | 지도에서 부스 위치를 눌러 상세 화면으로 이동 |
| QR 웨이팅 | 웹 카메라로 부스 QR을 인식하거나 QR 링크로 진입해 접수. 같은 브라우저 대상 활성 대기표 복원, 순번·예상 대기 시간을 확인하거나 접수 취소 가능 |
| 부스 운영 | 관리자가 대기 명단 조회, 호출·재호출·입장·노쇼·취소 처리, 접수 상태와 팀당 예상 시간을 설정하고 QR 이미지 다운로드 |
| 혼잡도·알림 | 무대 구역별 혼잡도와 추정 인원을 기록, 방문객은 홈에서 혼잡도를 확인하고 알림함에서 호출 알림과 읽음 상태를 관리 |

## 4. 실행 방법

### 필수 환경

- Node.js 22.12 이상 및 npm
- 웹 카메라를 통한 QR 인식에는 카메라 권한과 브라우저의 보안 컨텍스트가 필요합니다.

### 의존성 설치

프로젝트 최상위 폴더에서 실행합니다.

```sh
cd KUFIM-FE
npm ci
```

### 개발 서버 실행

전달받은 개발 환경 설정을 `.env.local`에 적용한 후 실행합니다. 접속 주소와 인증 정보는 별도로 관리합니다. 기본 설정에 원격 연결 대상이 포함되어 있으므로 실행 전에 사용할 개발 환경을 확인해야 합니다.

```sh
npm run dev
```

### 빌드·검증

프론트엔드 폴더에서 실행합니다.

```sh
npm run build
npm run lint
npx playwright install chromium
npm test
```

- `npm run build`: 정적 결과물을 `KUFIM-FE/dist/`에 생성합니다.
- `npm test`: API 응답을 테스트 데이터로 제어하는 브라우저 테스트를 실행합니다.

## 5. 구조 및 동작 방식

```text
KUFIM-FE/
├── src/
│   ├── pages/         # 사용자·관리자 화면
│   ├── components/    # 공통 UI·레이아웃·지도
│   ├── apis/          # 요청·타입·응답 변환·실시간 연결
│   ├── hooks/         # 도메인별 호출·조회 상태 관리
│   ├── app/           # 인증·축제 데이터 상태
│   └── router/        # 화면 경로·관리자 진입 구성
└── tests/             # 화면 동작·연동 테스트
```

### 화면 데이터 처리 흐름

1. 방문객이 축제 정보나 부스를 선택하면 관련 데이터를 조회하고 화면에 표시할 구조로 변환합니다.
2. QR 인식 결과로 접수 화면에 진입하고, 접수 후 자신의 대기 상태를 확인합니다.
3. 변경 이벤트를 수신하면 필요한 데이터를 다시 조회합니다. 실시간 연결을 사용할 수 없는 환경에서는 주기적으로 조회해 화면을 갱신합니다.
4. 사용자·관리자 화면에서 로딩·빈 목록·오류·재시도 상태를 구분해 표시합니다.

## 7. 기술적 문제 해결

### 지도 위 부스 위치 표시와 확대·이동 시 좌표 유지

**문제**

지도에 부스를 표시하고, 관리자가 지정한 위치를 사용자 화면에서도 동일하게 보여주는 방식을 정하는 데 어려움이 있었습니다. 화면의 픽셀 좌표를 그대로 사용하면 도면의 표시 크기와 확대·이동 상태에 따라 위치가 달라지는 문제가 있었습니다.

**해결 과정**

화면 좌표와 도면 좌표를 구분하고, 부스 위치를 도면 기준 0~100%의 상대 좌표로 표현했습니다.

지도 이미지와 마커는 같은 컨테이너 안에서 함께 확대·이동하도록 구성했습니다. 관리자가 지도를 클릭하면 이동량과 배율을 역산해 도면상의 위치를 구하고, 이를 퍼센트 좌표로 변환해 저장하도록 구현했습니다.

또한 지도를 드래그한 뒤 클릭 이벤트가 발생해 상세 화면으로 이동하거나 위치가 선택되지 않도록, 드래그 이후에는 클릭 동작을 막았습니다.

**구현 결과와 검증**

도면의 표시 크기가 달라져도 같은 상대 위치에 마커를 표시하고, 관리자 화면에서 부스 위치를 선택·저장할 수 있도록 구현했습니다.

확대·이동 시 마커 정렬, 드래그와 클릭 구분, 확대 상태에서 좌표 저장과 취소, 모바일 핀치 동작을 확인하는 테스트 시나리오도 마련했습니다.

## 8. 결과 및 회고

### 현재까지 구현한 범위

시연용 사용자·관리자 화면과 서버 데이터 연동을 완료했습니다. 화면 이동·오류 처리·세션 복원과 QR 접수·호출·입장 흐름을 확인하기 위한 브라우저 테스트를 작성했습니다.

이 문서를 수정하는 과정에서 테스트를 다시 실행하지는 않았습니다. 실제 축제에서의 사용 규모와 운영 성능은 10월 28일 필드테스트를 통해 확인할 예정입니다.

### 남은 과제

- 외부 문자 서비스를 연동해 SMS 호출 안내를 제공할 계획입니다.
- 현장 사용 전 실행 환경별 실시간 갱신 동작을 확인할 예정입니다.
- 현장 트래픽 대응, 보안, 운영 안정성을 추가로 점검할 예정입니다.

### 배운 점

이 프로젝트는 AI를 적극적으로 활용하며 직접 개발한 첫 사례입니다. 서비스 기획과 UI 설계를 실제 화면으로 구현하면서 AI를 개발 과정에 활용하는 방법을 익혔습니다.

동시에 AI가 코드를 제안하더라도 서비스가 의도대로 동작하는지는 직접 확인해야 한다는 점을 배웠습니다.
뒤로가기 흐름이나 지도 위 부스 표시처럼 화면 간 맥락과 좌표 처리가 필요한 기능은 원하는 동작을 구체적으로 정의하고, 
제안된 코드가 요구사항에 맞는지 확인해야 했습니다. 외부 문자 서비스처럼 실제 환경과 연결되는 작업은 아직 해결할 과제로 남아 있습니다.

일정 규모의 서비스를 현장에 투입할 준비를 하면서 화면과 기능 구현뿐 아니라 보안·트래픽·운영 조건까지 고려해야 한다는 점도 배웠습니다.
앞으로는 AI가 제안한 코드를 이해하고 수정하는 역량을 쌓고, 실제 현장에서 필요한 기능인지 판단하고 검증하는 경험을 이어가고자 합니다.

### 향후 계획

2026년 10월 28일 축제에 도입해 방문객과 운영진의 사용성을 확인하고, 현장 운영에 어떤 영향을 주는지 평가할 예정입니다.
이후에는 스탬프 투어, 신고 접수·처리, 굿즈 구매 기능을 추가하고자 합니다. 현재 신고 메뉴는 안내 화면까지만 구현했으며, 신고 접수와 처리 기능은 추후 개발할 계획입니다.
